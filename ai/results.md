## 2026-10-16 - Sprint 6: the preview splits long text the way the server will
- Mode: Debug -> Build. Closed open item "X preview disagrees with what will be posted".
- Cause (read + proven): server `PostSplitter::chunk()` breaks an over-limit paragraph on words
  (then characters); the client `packSections()` only packed whole paragraphs, so the preview
  showed one oversized post. The shared parity fixture had no over-limit case. The counter's
  "Single post" read the page-load targets, not the live text.
- What changed (marked "SocialApp change:"):
  - `lib/compose/section-split.ts`: `chunkSegment()` (+ `splitParagraph`, `hardSplit`) - exact
    port of the server; ASCII-only whitespace split to match PCRE `\s`; `previewSections()` uses
    it. `packSections()` unchanged (editor paragraph markers).
  - `lib/compose/platform-preview.ts`: auto-split path uses `chunkSegment()`.
  - `components/compose/composer.tsx`: `liveSections()` drives the counter thread size and the tab
    chip; counter colour judged on the longest part.
  - New fixture `tests/Fixtures/post-splitter-overlimit-parity.json` (11 cases) **generated by
    running the real server splitter** (`scripts/gen-splitter-fixture.php`), checked by
    `tests/Unit/Posts/PostSplitterOverlimitParityTest.php` and `section-split.test.ts`.
  - Updated tests: `platform-preview.test.ts` (Bluesky case now expects the server's 3 parts -
    verified by running the server splitter on that exact text), `composer-tabs.test.ts`.
- Acceptance criteria:
  - 318-char post previews as a 2-part X thread identical to the server's saved parts: met (seen;
    server target: 276 "...Book a 15-minute" + 41; preview shows the same split).
  - Counter "2-post thread" live: met (seen). X tab chip "2", LinkedIn "1": seen.
  - Fixture parity both sides: met (11/11 PHP, 11/11 TS).
  - Auto-split OFF unchanged: code path untouched (`!autoSplit` branches), not seen in the browser.
  - LinkedIn one post: met (seen, chip 1; server saved 1 part).
  - PHP **2055 passed**, Pint clean; JS **920/921** (1 known baseline), oxlint 0/0, oxfmt exit 0,
    tsc exit 0. (Larastan: no app/ PHP changed this sprint.)
  - Browser: composer + preview + Publish now window (fake accounts, cancelled, nothing published).
- Review findings:
  - An upstream test pinned the wrong preview behaviour (Bluesky 38-char paragraph kept whole);
    corrected to the server's real output rather than kept for green.
  - Counter now amber at 318 because part 1 is 276/280 (>= 90%): a fair warning, not an error.
  - Known gap kept (as planned): in a multi-paragraph post the editor's inline marker still shows an
    over-limit paragraph's own count in red. -> `ai/tasks.md`.
- Commit: see git log ("Sprint 6: ...")
